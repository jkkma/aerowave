# Aerowave 0.16.0 prerelease

This Windows-only prerelease adds an offline emergency alarm tone, safer settings
recovery, one-shot completion protection, a consolidated readiness check, and
Windows/Linux regression CI.

## Changes

- Desktop alarms switch to a synthesized native emergency tone when the primary
  source and backup music cannot play. Its output is independent of the WebView,
  network and media codecs, with occurrence-safe Dismiss/Snooze, volume and fade
- Unreadable settings stay untouched and ordinary writes are blocked until
  recovery. Backup restore preserves original bytes before replacement; uncertain
  post-rename saves require readback before later writes
- One-shot alarms use a session guard plus independently saved completion
  receipts and settings. Failed saves retry; stale editors cannot silently rearm
  completed alarms, and legitimate snoozes stay eligible
- Alarm readiness inspects next alarm, saved source, backup, storage, and platform
  limitations without playing sound. The Android source includes media-volume,
  mute and available-output checks, with production bridge serialization coverage
- Includes the existing Android silent-preparation and MIUI/DND alarm-screen
  recovery fixes already on main after 0.15.3

## Validation and limits

The release workflow gates the Windows package on frontend, Python/repository,
Rust core and native Windows/Linux compile checks for this exact source commit.
The development verification also passed 11 Store filesystem/fault tests.

This remains a prerelease because packaged Windows playback, emergency-tone
sound, and unattended wake have not been qualified on real hardware. A readiness
check, granted permissions, file discovery or a foreground preview does not
establish audible screen-off wake. Muted/disconnected outputs, stopped apps,
Modern Standby and platform restrictions can still prevent alarms; a shut-down
PC cannot run one. Use a separate dependable alarm while qualifying this build.

If both one-shot completion writes fail, the running process still prevents a
repeat, but exiting/crashing before either write succeeds can repeat it after
restart. Settings explicitly warns to keep the app open until it saves.

No Android APK is included. Signed Android distribution requires the original
Windows-DPAPI-backed signing setup, Android JVM/build checks and device validation.
A debug or differently signed APK is not an update for the installed release.
The stable Scoop manifest remains on the last qualified release.

The portable Windows executable is not code-signed; Windows SmartScreen may show
an unknown publisher. The ZIP's SHA-256 and exact source commit are appended by
the publishing workflow. Portable settings live beside the executable under
`data`; this does not migrate an installed copy's existing settings automatically.

See [the qualification checklist](https://github.com/jkkma/aerowave/blob/v0.16.0/docs/alarm-reliability-testing.md) and
[Android signing instructions](https://github.com/jkkma/aerowave/blob/v0.16.0/docs/android-release.md) before stable
promotion or signed Android publication.
