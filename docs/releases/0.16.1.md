# Aerowave 0.16.1

Android alarms now fade out over six seconds when their automatic timeout
stops or snoozes them. The fade applies to radio, backup music and system tones.
Manual Dismiss, Snooze and volume-button actions remain immediate, including
during a fade. A failed save or snooze schedule restores playback and keeps the
controls available for another attempt.

## Alarm fixes

- Returning from a snooze preserves an independently re-enabled one-shot alarm.
- Rebuilding a one-shot more than 15 minutes late consumes it instead of
  unexpectedly scheduling it for the next day.
- Editing the time or repeat days replaces an old catch-up occurrence while
  preserving genuine snoozes. Label and source changes retain catch-up behavior.
- A default system tone that never starts or later stops can recover through the
  alternate notification tone. Candidate recovery is bounded and preserves an
  automatic fade already in progress.
- Cold Android alarm startup posts its foreground notification before player
  initialization and holds the CPU through the receiver-to-service handoff.

Either volume button snoozes a ringing Android alarm, and a firm shake dismisses
it. Settings also offers **Alarm diagnostics > Export alarm logs**. This bounded
history survives process restarts and excludes raw audio, source URLs and folder
paths. Review exports before sharing them because they retain alarm times and
device state.

The Windows package includes the native offline emergency tone, safer settings
recovery, durable one-shot completion protection and alarm readiness checks from
0.16.0. Android readiness also checks media volume, mute and available outputs.

## Packages and qualification

This release includes the Windows x64 portable ZIP and a signed, optimized
Android ARM64 APK. The APK uses the existing release certificate and upgrades
the installed app without uninstalling it. The Windows executable is not
code-signed; SmartScreen may identify an unknown publisher. Package SHA-256
values and validation results are recorded in the published release notes.

Short device checks and automated fault tests do not qualify an unattended
night, Bluetooth routing, credential-locked reboot or every manufacturer's
battery restrictions. Audio decoding and volume commands do not establish
subjective sound or fade quality. Modern Standby and a shut-down PC can prevent
desktop alarms. See the [Android qualification record](../android-qualification.md)
and [alarm reliability checklist](../alarm-reliability-testing.md) for the
evidence and remaining limits.
