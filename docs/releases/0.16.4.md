# Aerowave 0.16.4

Browse now finds station artwork as search results become visible, including
when the directory's preferred submission has a missing, dead or corrupt logo.
Artwork recovery matches the exact stream address and can use another matching
submission without starting playback.

Rapidly scrolling through results no longer drops artwork when the request
queue fills. Waiting rows resume as capacity becomes available, while a new
search cancels obsolete work. Loading stays limited to four active requests
and thirty-two queued requests. Playback can fill an empty result thumbnail,
and a late background lookup cannot replace that recovered picture.

Saving a result during settings recovery now explains that the operation must
be retried. It cannot leave the row stuck at "Saving..." or silently queue an
addition behind recovery. A station write already accepted before recovery
still completes normally, and failed additions remain available to retry.

## Validation and package

Source validation passed 474 frontend tests, 234 Rust core tests and 44
repository-checker tests. Coverage includes artwork recovery before playback,
lazy loading, rapid scrolling, bounded requests, replaced searches, late
responses and settings-recovery success and failure.

The Windows x64 portable ZIP retains settings in its adjacent `data` folder;
Scoop persists that folder across updates. The executable is not code-signed.
Package hashes and completed native Windows validation are recorded in the
published release notes. Automated playback checks establish decoding and an
advancing playhead, not physical speaker audibility.
