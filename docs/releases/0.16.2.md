# Aerowave 0.16.2

**Android signing key change:** the original release key is no longer
available. This APK uses a new certificate and cannot update 0.16.1 or older
installations in place. Export your setup backup before uninstalling the old
app, install this APK, then restore the backup and grant notification, exact
alarm and music-folder access again. Restored alarms start off; review and
enable them deliberately. See [Android release migration](../android-release.md).

New certificate SHA-256:
`33291249748AEDC99F2275C8BD8C0B621A2ED79821F22022DFF3C77B4BB0CA53`.

This release fixes Android alarm failures found through adversarial code review,
fault injection and testing on a connected Android 13 phone.

## Alarm scheduling and saved state

- Opening Aerowave restores its native scheduled clocks after a force-stop.
  Android continues to suppress alarms until the force-stopped app is opened.
- Saving an editor left open while a one-shot finished cannot silently rearm
  that alarm for tomorrow.
- An abandoned ring or failed service handoff cannot defer future alarms
  indefinitely. Deferred occurrences retain their original expiry deadline.
- A failed schedule save preserves the previously armed Android clocks.
  Failure to arm a future occurrence does not prevent the current ring starting.
- Failed native reads preserve the authoritative alarm list and block writes
  until refresh succeeds. Settings recovery cannot overwrite native source
  information with temporary defaults.
- Failed station or backup-folder synchronization stays visible in readiness
  checks, with a retry path.

## Alarm sound recovery

- Permanent audio-focus loss allows a bounded recovery attempt when competing
  playback or a call has ended, plus an explicit **Resume sound** control.
- Folder and station selection have a deadline independent of a blocked
  provider. Work uses a bounded pool and falls back when both workers are busy.
- Late source replies cannot interrupt a fallback tone that has started.
- A dead nested playlist does not discard the remaining playable candidates.

## Qualification limits

Local validation passed 449 frontend tests, 308 Android JVM tests, 234 Rust
tests, 44 repository-check tests and the Linux native compile check. A separate
review installation on the Android 13 phone passed force-stop/reopen repair,
stale-editor protection and delivery after an abandoned test ring. The existing
signed installation was preserved. See the dated
[device qualification record](../android-qualification.md).

Automated tests and renderer diagnostics do not establish physical speaker
audibility; the October 3 phone checks had no listening confirmation.
Unattended overnight delivery, every manufacturer's background restrictions,
credential-locked reboot and all Bluetooth routes remain separate qualification
work. Package hashes and completed validation are recorded in the published
release notes.
