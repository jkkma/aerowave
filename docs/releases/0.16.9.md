# Aerowave 0.16.9

## Station playback

- The station probe and relay preserve Basic Auth on the same scheme, host
  and port. HLS segments can use their own credentials.
- The ordinary relay reconnects from the submitted URL. Desktop playback
  starts recovery after 30 seconds without decoded progress, even if the
  connection stays open. Desktop alarm fade-in starts when playback succeeds,
  including after a direct LAN connection takes over.
- Android HLS retries can resolve a fresh manifest from the submitted station
  URL. The native player restricts HLS playlist and segment requests to public
  HTTP(S) destinations.

## Browse and saved stations

- Browse accepts public station addresses. Manual entry still supports LAN
  stations. Directory artwork lookups skip private addresses and URLs
  containing credentials, query strings or fragments.
- When Browse combines duplicate submissions, it still recognises the other
  addresses when matching saved and playing stations. Android validates station
  URLs before saving them.
- Saving a Recent station preserves its link through later edits and restarts.
  Setup backups preserve that link and accept repeated Recent entries for the
  same stream.

## Validation and Windows package

Local checks passed 532 frontend tests, 44 repository checker tests, 258 Rust
core tests and 314 Android JVM tests. The network example passed 11 tests and
10 local fixtures. The Windows build produced an x64 executable and NSIS
installer. ZIP checks verified the executable’s version, archive contents and
hash. Native application playback and speaker audibility were untested.

The Windows x64 portable ZIP keeps settings in the adjacent `data` folder.
Scoop persists that folder across updates. The executable is unsigned.
